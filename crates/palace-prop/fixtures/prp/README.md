# `.prp` golden fixtures

Byte-stable `.prp` container fixtures for the roster model and writer. They exist
so the container can be tested without the 200 MB of real collections in
`$MEDIA/Prop Files/`, and so `tests/fixtures.rs` can pin the format with the
crate's existing public prop API (`decode`, `payload_crc`).

The six `*.prp` synthetic files are generated by
`crates/palace-prop/validation/make_prp_fixtures.py` from the small real prop
blobs already checked in one directory up (`fixtures/*.bin`). Regenerate with:

```text
python3 crates/palace-prop/validation/make_prp_fixtures.py
```

## Synthetic fixtures

All six are canonical server shape: records sorted ascending by **signed** id,
blobs packed contiguously, `crc = asset_crc(blob[12:])`, and
`filesize == assetMapOffset + assetMapSize`.

| File | Bytes | Structure it covers |
|---|---|---|
| `single_type.prp` | 2200 | One `Prop` type, no `Fave`. A high-bit id (`0x803D6C40`, negative when signed) sorts before a small positive one (`0x3A3AD1F7`). Two named records. |
| `prop_fave.prp` | 2170 | `Prop` + `Fave`, with the `Fave` size-0 sentinel (`id 128`, `nameOffset -1`). |
| `dup_id_crc.prp` | 1779 | One id (`1000`) carried by three adjacent crc variants, plus a different id whose crc equals the first variant. |
| `empty.prp` | 52 | A valid file with a `Prop` type and zero records, no names. |
| `unnamed_records.prp` | 1147 | Two `Prop` records, both `nameOffset = -1`; empty names blob. |
| `long_nonascii_name.prp` | 2317 | A 196-byte latin1 name mixing high bytes (`0xE9`, `0xF1`, `0xFA`, `0xDC`). |

## Real fixture

`real_palace_hidden.prp` (73,443 bytes) is a byte-for-byte copy of
`Palace - Hidden.PRP` from the user's own local archive.

```text
a06ad1fc76616d2011d3bf1cc4cfa6c478937aac4c40121af9d584ffbb3fd789  real_palace_hidden.prp
```

It is included because it is the smallest real collection and it pins the messy
reality the synthetic files cannot: 76 records over `[Prop, Fave]`, 56 of them
named, records **not** sorted by id, blobs at scattered offsets, one `Prop`
record whose stored CRC does not match its payload, and a `Fave` record that
carries an 8-byte `(id, crc)` payload rather than the size-0 sentinel.

Licensing: Palace props are 1990s/2000s user-generated content of unknown
individual authorship. This crate already ships real prop blobs under
`fixtures/*.bin` with the same provenance posture, and this file is included as
test data under the repository's GPL-3.0-or-later licence. If a purely synthetic
tree is ever required, delete `real_palace_hidden.prp`; the six synthetic files
already cover every structural case and `tests/fixtures.rs` skips the real-file
assertions only if that file is absent.

## The oracle caveat

`$CORPUS/tools/rebuild_prp.py` is **not** byte-exact on any of these files,
including the canonical ones. It flattens types to `[Prop, Fave]`, synthesises
the `Fave` record (zeroing its `dataOffset`), reorders records, and in its default
mode merges in a 180,550-id blob pool. It is a canonicaliser/merger, not a
round-trip oracle. The full per-file evidence is in
`.omo/evidence/task-5-python-oracle.txt`.
